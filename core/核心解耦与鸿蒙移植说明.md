## 一、为什么解耦

原引擎全部逻辑内联在 `UI/大六壬万年历起课.html`（约1350行，纯计算与 DOM 渲染混在一起）。目标：
1. **五端复用**（Web/H5、小程序、鸿蒙 ArkTS、安卓 WebView、Python）
2. **规则只改 JSON**（旺衰/神煞/毕法/断语数据全端同步生效）
3. **鸿蒙近复制**（真源按 ArkTS 兼容子集写，迁移不返工）

## 二、架构（真源 → 编译产物 → 各端）

```
真源   core/liuren-core.ts        ← ArkTS 兼容子集 TypeScript（零 DOM、纯计算）
        │  npx tsc（无 import/export，产出浏览器全局脚本）
        ▼
编译   core/liuren-core.js        ← Web/H5、小程序、安卓 WebView 直接 <script> 加载
        │  近复制（按 ArkTS 模块惯例加 export）
        ▼
鸿蒙   APP/LiurenFocusDiviner/.../LiurenCore.ets
        │  算法同构（读同一批 JSON 规则数据）
        ▼
Python liuren_core.py             ← 算法照搬
```

**规则数据（12 个 JSON）不随语言变**——四端改规则只改 JSON。

## 三、核心 API（`class LiurenCore`）

### 规则注入
```typescript
LiurenCore.init({
  duxiang: window.DUXIANG_RULES,   // 读象规则：旺衰/气机点/空亡/助日/基础关系
  shensha: window.SHENSHA_RULES,   // 神煞起法（35神煞）
  bifa:    window.BIFA             // 毕法赋一百法（含判定+定位模板）
});
```

### 排盘（唯一入口）
```typescript
const chart: Chart = LiurenCore.buildChart({
  date: '2026-01-08',     // 'YYYY-MM-DD'
  hourZhi: '酉',          // 占时地支
  calData: window.CAL,    // 历法数据（1900-2060 分片）
  yjAll:   window.YJ_ALL  // 月将数据（中气换将秒级）
});
// chart 含：r(四柱) yj(月将) tp(天盘) kegs(四课) dun(遁干)
//          sanchuan(九宗门三传) jiangMap(天将布列) gui/shun/night/hourGan
//          dx(盘态)：
//            xunkong 旬空 | dayWangShuai 日干旺衰
//            nodes[支]{wangShuai,qiJi,kong} | relations[支]{chong,he,hai,xing}
//            yuejiang.zhu / guiren.zhu  月将·贵人助日
//            shensha.byZhi[支]=[神煞名...]  shensha.list(35)
//            bifa=[{序,法名,赋文,判}]  本课格局
```

### 其余静态方法
| 方法 | 说明 |
|---|---|
| `computeDuxiang(c)` | 盘态（旬空/旺衰/气机点/冲合刑害/助日/神煞/格局） |
| `computeShensha(c)` | 35 神煞落位（岁/季/月/旬/干/支六基准查表） |
| `bifaForChuans(c, chu)` | 格局判定（chu 可传本课或动态三传，用神即初传） |
| `renderBifaForChuans(c, dx, chu, aff)` | 五层定位（定性/定象/定时/定策/定级）+ 条件分支评估 + 占事过滤 |
| `dunMap / gongOf / findYuejiang / resolveSanchuan / hourGan / wxOf / ke / SHENG / wutun` | 底层工具 |
| 常量 `GAN ZHI JI_GONG WX WXG KE GUIREN JIANG_SHUN JIANG_NI BENSHEN JIANG_JX YANG_ZHI G_YANG` | 静态成员 |

## 四、ArkTS 兼容性（真源合规清单）

已遵守（`鸿蒙规范文档/ArkTS开发规范指南.md`）：
- ✅ 零 `any`/`unknown`（代码中仅注释提及）
- ✅ 全显式类型：所有函数参数/返回/数据结构都有 interface
- ✅ 查表用 `Record<string,string>`（ArkTS 允许，✅推荐）
- ✅ 无对象 `for-in`（用 `Object.keys` + 类型断言）
- ✅ 无内联对象字面量类型、无解构/展开/可选链/`??`
- ✅ 静态方法内部一律 `LiurenCore.xxx()` 调用
- ⚠️ 待移植微调：`static rules: CoreRules = { duxiang: {}, shensha: {}, bifa: {} }` 的空对象字面量，.ets 移植时改为显式类型初始化
