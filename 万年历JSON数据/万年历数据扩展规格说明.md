# 万年历数据扩展规格说明

> 面向 **大六壬、奇门遁甲、八字** 等国学排盘软件的历法数据扩展方案。
> 本文件是**规格**（先定规格、再补数据）；对应数据的生成与校验方案见第 7 节。
> 配套文件：《万年历json数据说明.md》（现有数据说明）。

---

## 1. 目标与原则

### 1.1 目标
在现有 1900-01-01 ~ 2060-12-31 逐日数据（58,805 条）基础上，补齐排盘软件所需的**时刻级**与**规则级**数据，使其足以支撑：

- **大六壬**：月将、十二时辰、昼夜、旬空、神煞、纳音、十二长生、天将布法；
- **奇门遁甲**：节气交接时刻（置闰/拆补/茅山定局）、三元局数、九星八门八神、值符值使、马星空亡；
- **八字/通用**：立春换年柱、精确月柱（节为界）、日柱换日约定、真太阳时。

### 1.2 原则
1. **只读原则**：现有 `json/`、`calendar.csv/.db/.xls` 一律**不改动**，保持原始数据可追溯；
2. **数据与规则分离**：历法数据（时刻、逐日）与静态规则（神煞、局数、纳音）分文件存放；
3. **修正以新增落地**：对原数据中必须修正的字段（年柱、月柱），生成独立的《修正主表》，不覆盖原文件；
4. **可校验**：每个新文件必须附生成算法与校验方式，全部差异归零才算通过（见第 7 节）。

## 2. 现有数据问题清单（已实测确认）

| # | 问题 | 实测证据 | 影响 | 处理方式 |
| --- | --- | --- | --- | --- |
| 1 | **年柱按农历春节换，不符合命理惯例** | 2024-02-04（立春当天）数据年柱为「癸卯」，2-10（春节）才换「甲辰」；而月柱 2-04 已按立春换「丙寅」——年柱春节换、月柱节气换，两套规则混用 | 八字/奇门/六壬年命在「立春~春节」窗口期错误（2024、2052 等年份） | 修正主表中新增 `year_gan_zhi_lichun`（立春纪年），原字段保留为春节纪年 |
| 2 | **全表无时刻信息** | 全量检索无 `HH:MM` 字段；节气仅日期 | 奇门置闰/拆补定局、月将换将、月柱换界无法精确到时刻 | 新增节气时刻表 `solar_terms.json` |
| 3 | **月柱换月日期为近似值** | 2024 年大雪实为 12-07，数据 12-06 即换「丙子」月；2020/2049 等多处 ±1 天 | 月柱在临界日错误 | 修正主表按节气时刻表重算月柱 |
| 4 | **缺小寒、大寒** | 全年仅 22 个节气，缺公历 1 月两个 | 节气不完整 | 节气时刻表补齐 24 节气 |
| 5 | **未经权威校验** | 闰月/大小月/日干支来源不明 | 可信度风险 | 用寿星天文历全量校验并出报告 |
| 6 | `is_holiday` / `holiday_name` 为空 | 全表 0 / "" | 非排盘核心 | 保留字段，另行补充法定节假日（可选） |

## 4. 分层架构

排盘软件的数据流：

```
① 历法基础层（现有+修正主表）  逐日：公历、农历、干支日、星期
② 时刻事件层（新增）          节气交接时刻、月将换将时刻
③ 静态规则层（新增）          神煞、纳音、长生、局数、二十八宿、建除黄道、时辰
```

排盘流程：`公历时刻 → (②) 定干支历/节气 → (①) 取日干支 → (③) 起局/起课`。

## 5. 各文件规格

### 5.1 `ext/solar_terms.json` — 节气时刻表（核心）

24 节气 × 161 年（1900~2060）共 **3,864** 条，`{ "index", "name", "type", "solar_date", "solar_time", "unix_utc8", "zodiac_year_gz", "month_gz" }`：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `index` | int | 全局序号（1900 立春起递增） |
| `name` | string | 节气名：立春、雨水、…、大寒（**含小寒、大寒，共 24 个**） |
| `type` | string | `节` / `气`（节=换月柱的 12 个，气=换月将的 12 个） |
| `solar_date` | string | 交接日期 `YYYY-MM-DD`（东八区） |
| `solar_time` | string | 交接时刻 `HH:mm:ss`（东八区，秒级） |
| `unix_utc8` | int | 东八区时间戳（秒），便于排序与复核 |
| `year_gz_lichun` | string | 交接时刻所处**立春纪年**年柱（八字/奇门用） |
| `month_gz` | string | 交接时刻所处月柱（**节**交接当刻即换月柱） |

生成：寿星天文历（`sxtwl`）逐秒求解；校验见第 7 节。

| --- | --- | --- | --- | --- |
| 雨水 | 330° | 登明 | 亥 | 正月将 |
| 春分 | 0° | 河魁 | 戌 | 二月将 |
| 谷雨 | 30° | 从魁 | 酉 | 三月将 |
| 小满 | 60° | 传送 | 申 | 四月将 |
| 夏至 | 90° | 小吉 | 未 | 五月将 |
| 大暑 | 120° | 胜光 | 午 | 六月将 |
| 处暑 | 150° | 太乙 | 巳 | 七月将 |
| 秋分 | 180° | 天罡 | 辰 | 八月将 |
| 霜降 | 210° | 太冲 | 卯 | 九月将 |
| 小雪 | 240° | 功曹 | 寅 | 十月将 |
| 冬至 | 270° | 大吉 | 丑 | 冬月将 |
| 大寒 | 300° | 神后 | 子 | 腊月将 |

结构：每年一个对象数组（12 段），每段 `{ "start_unix_utc8", "end_unix_utc8", "yue_jiang", "zhi" }`。**由 `solar_terms.json` 直接派生**，不单独计算。

| 旬 | 日干支区间 | 空亡（地支） |
| --- | --- | --- |
| 甲子旬 | 甲子 ~ 癸酉 | 戌、亥 |

### 5.4 `ext/na_yin.json` — 六十甲子纳音（静态 60 条）

字段：`{ "gan_zhi", "na_yin", "element" }`。
例：甲子=海中金(金)、丙寅=炉中火(火)、戊辰=大林木(木)、庚午=路旁土(土)、壬申=剑锋金(金)…（甲子至癸亥全部 60 组）。

### 5.5 `ext/chang_sheng.json` — 十二长生（静态 10×12）

字段：`{ "gan", "zhi", "state" }`，`state` ∈ 长生、沐浴、冠带、临官、帝旺、衰、病、死、墓、绝、胎、养。
阳干顺行、阴干逆行（甲木长生在亥，乙木长生在午…）。

### 5.6 `ext/shen_sha.json` — 神煞查法表（静态规则）

每条神煞一个对象：

| 字段 | 说明 |
| --- | --- |
| `name` | 神煞名 |
| `category` | `year`（年煞）/ `month`（月煞）/ `day`（日煞）/ `time`（时煞） |
| `basis` | 查法基准：年支、月支、日支、日干、月将… |
| `rule` | 结构化查法（如 `寅午戌马在申` 存为 `{x:["寅","午","戌"], result:"申"}` 或口诀文本） |
| `schools` | 适用：`六壬` / `奇门` / `择日` / `通用` |

首批建议收录（可后续扩充）：

- **六壬核心**：天乙贵人（阳贵/阴贵两套：甲戊庚牛羊、乙己鼠猴乡、丙丁猪鸡位、壬癸兔蛇藏、六辛逢马虎）、驿马、桃花（咸池）、华盖、劫煞、亡神、天喜、天德、月德、天赦、月厌、丧门、吊客、病符、官符、五鬼、天网、死神；
- **奇门核心**：驿马（申子辰马在寅…）、空亡（旬空）、入墓（木墓未、火墓戌、金墓丑、水土墓辰）、刑冲合害破；
- **择日通用**：天德、月德、天德合、月德合、天赦、天愿、母仓、四相、时德、黄道/黑道。

> 注：神煞各家查法存在流派差异，表中须标注出处/流派，供排盘软件按流派选用。

## 6. 基准与约定（排盘软件必须明确）

### 6.1 时区
- 数据基准：**东八区（UTC+8）北京时间**；
- 1900~2060 年中国标准时均为 UTC+8（1901 年前地方时差异不另作处理，如需可标注）；
- 时间戳字段 `unix_utc8` 便于跨时区换算。

### 6.2 真太阳时（可选，精度要求高时）
排盘软件可选启用**真太阳时**：
`真太阳时 = 北京时间 + (当地经度 − 120°) × 4 分钟 + 均时差`
- 数据层提供：均时差年度表或计算公式（可选新增 `eq_time.json`）；
- 默认关闭，使用北京时间。

### 6.3 子时换日约定
- **默认约定：子初（23:00）换日**，即 23:00~24:00 的「晚子时」日柱用**次日**干支（与八字主流一致）；
- 提供配置项可切换为「子正（0:00）换日」流派；
- 修正主表的 `day_gan_zhi` 以 0:00 为基准存储，软件按约定自行处理 23:00~24:00。

### 6.4 昼夜判定（六壬贵人起法）
- 精确方案：按当地**日出/日落**时刻（需经纬度）；
- 简化方案（默认）：卯时（05:00）起为昼，酉时（19:00）起为夜；昼占用阳贵、夜占用阴贵。

## 7. 生成与准确度保障方案

### 7.1 生成工具
- **寿星天文历 `sxtwl`**（Python，开源，算法源自《寿星天文历》，农历范围 1900~2100 与紫金山天文台数据一致，节气交接时刻可达秒级）作为主生成器；
- 生成项：节气时刻表、农历（闰月/大小月）、日干支、年柱/月柱（按节气时刻）。

### 7.2 交叉验证（双库独立校验）
用第二个独立实现 **`lunar_python`（6tail）** 全量复核：

| 校验项 | 范围 | 容限 |
| --- | --- | --- |
| 农历年月日、闰月标记 | 58,805 天 | 完全一致 |
| 日干支 | 58,805 天 | 完全一致 |
| 节气日期 | 3,864 条 | 完全一致 |
| 节气时刻 | 3,864 条 | 差 ≤ 1 秒（或完全一致） |
| 年柱（立春）/ 月柱 | 58,805 天 | 完全一致 |

### 7.3 权威锚点抽样比对
与公开的权威节气时刻比对（北京时间），例如：

| 节气 | 权威时刻（东八区） |
| --- | --- |
| 2024 立春 | 2024-02-04 16:26:53 |
| 2024 冬至 | 2024-12-21 17:20:20 |
| 2025 立春 | 2025-02-03 22:10:13 |

抽样不少于 20 个年份、覆盖四季，全部一致才通过。

### 7.4 现有数据全量校验报告

### 9.1 与原规格的偏差

| 项 | 原规格 | 实测与处理 |
| --- | --- | --- |
| 生成工具 | `sxtwl` | sxtwl 无 Python 3.14 预编译包且本机无 C++ 编译器，改用 **lunar_python**（主）+ **skyfield/JPL de422 星历**（节气时刻，权威）+ **cnlunar**（备用） |
| 月柱（day 粒度） | 预计有 ±1 天误差需修正 | **实测与权威逐日 100% 一致**（58,805/58,805），无需修正；真正的 ±1 天误差在原数据的 `solar_term` **日期**字段 |
| `solar_term` 日期 | 仅缺小寒/大寒 | 实测另有 **1,421 个节气日期标错 ±1~2 天**（如 1900 年惊蛰），修正主表与节气时刻表均按权威值补齐 |
| 农历 | 预计一致 | 实测 **30 天不一致**（2057-09-28 ~ 10-27，2057 年农历八月朔日/大小月分歧），修正主表采用寿星天文历值 |
| 节气时刻精度 | 秒级、双库差 ≤1 秒 | skyfield(JPL) 与 lunar_python 互验：日期 3,862/3,864 一致（2 个跨午夜边缘节气：1911 立夏 23:59:46、1951 冬至 23:59:49）；时刻差中位数 3 秒、最大 46 秒（1900 年代） |
| 官方锚点 | 全部一致才通过 | 与国内官方公布值差 **12~15 秒**（如 2024 立春 16:27:07 vs 官方 16:26:53），属 JPL 星历与国内历表理论的正常差异，不影响时辰（2 小时）粒度排盘；香港天文台公布到分钟与本文一致。详见 `anchors_report.json` |
| 星期 | — | lunar_python `getWeek()` 为 0=周日..6=周六，已换算为 0=周一..6=周日（与现有数据一致），全量一致 |
