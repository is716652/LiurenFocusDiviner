# 大六壬项目付费架构方案（解耦 · 可移植）

> 目标：一次性买断制；测试期可开关；卸载/换机可恢复购买；与业务解耦、可移植到多个 APP。
> 依赖：华为 AppGallery Connect 商品配置 + 鸿蒙 IAP Kit（`@kit.IAPKit` / `@hmscore/iap`）。

---

## 一、架构分层（核心思想：业务不问"怎么付"，只问"开没开"）

```
┌─────────────────────────────────────────────────┐
│  业务层（大六壬）                                  │
│  PanDisk / 毕法 / 抓用神 / 中黄五变经 / 古籍案例      │
│        │ 只调用                                    │
│        ▼                                          │
│  PayGate（统一门禁）                                │
│  isUnlocked(featureId) → boolean                   │
│  内部：付费开关 && 购买状态 && 恢复购买               │
│        ▲                                          │
│        │ 实现                                     │
│  IapAdapter（支付适配器，可替换）                    │
│  - HuaweiIap（真实华为支付）                        │
│  - DebugIap（测试桩：一键解锁，供开发/测试）          │
└─────────────────────────────────────────────────┘
```

**关键解耦点**：业务代码里**永远不出现** `iap.xxx` 或商品 ID，只出现 `PayGate.isUnlocked('bifa_advanced')`。换支付平台（如未来上安卓/其他商店）只换 `IapAdapter`，业务零改动；换 APP 直接把 `PayCore` 文件夹复制过去。

## 二、模块划分（PayCore 独立目录，零业务依赖）

```
entry/src/main/ets/pay/
├── PayConfig.ets     // 商品清单（数据驱动，改 JSON 不改码）
├── PayGate.ets       // 统一门禁（业务唯一入口）
├── PayStore.ets      // 购买状态本地持久化（Preferences）
├── IapAdapter.ets    // 支付适配器接口 + 工厂
├── HuaweiIap.ets     // 华为 IAP 实现（obtainOwnedPurchases 恢复购买）
└── DebugIap.ets      // 测试桩（开关=测试模式时全部解锁）
```

### PayConfig：商品清单（单一事实来源）
```typescript
// 商品 = 功能 = 权益；一个商品可解锁多个 featureId
export interface PayProduct {
  productId: string;      // AppGallery 控制台配置的商品 ID
  name: string;           // 展示名
  desc: string;
  price: string;          // 展示价（实际以商店为准）
  featureIds: string[];   // 解锁的功能 ID 列表
  type: 'non_consumable'; // 一次性买断
}

export class PayConfig {
  static readonly MODE: 'free' | 'paid' = 'free'; // ★ 开关：测试期 free，上线改 paid
  static readonly PRODUCTS: PayProduct[] = [
    { productId: 'pro_full', name: '大六壬专业版', desc: '解锁高级读象与全文',
      price: '29.9', featureIds: ['bifa_advanced', 'duxiang_advanced', 'zhonghuang_full'], type: 'non_consumable' },
    // 后续新增商品只需在此追加
  ];
}
```

## 三、问题逐条解答

### 1. 收费开关（测试期不判断）
`PayConfig.MODE = 'free'` 时：
- `PayGate.isUnlocked(任何) → true`（全功能开放，测试无忧）
- 支付入口不显示、IAP 不初始化

`MODE = 'paid'` 时：
- 走真实判断：本地购买状态 → 若未买则查华为云端（恢复购买）

### 2. 哪些功能收费（大六壬版建议）
| 功能 | 免费/付费 | 理由 |
|---|---|---|
| 基础排盘（四柱/天盘/四课/三传/盘态） | 免费 | 核心体验，引流 |
| 天将/神煞/旬空 基础盘态 | 免费 | |
| **毕法 30 法格局判定（深入）** | 付费 | 专业价值高 |
| **抓用神 · 管辂读象（选句/节点卡）** | 付费候选 | 高端知识付费 |
| **课体识别（伏吟/返吟/八专/别责 详解）** | 付费候选 | |
| **中黄五变经全文（8-28 篇详解）** | 付费 | 稀缺古籍 |
| 古籍案例重演 | 付费 | 内容稀缺 |
| 合规页/设置 | 免费 | |

> 具体划线可再议；架构上支持"按 featureId 自由组合"。

### 3. 恢复购买（卸载/换机）——不需要自建服务器！
**华为 IAP 官方能力**：`obtainOwnedPurchases()` 通过**华为账号体系**返回该账号在云端的所有已购商品。

```
卸载重装 / 换新手机 → 用户登录同一华为账号 → 启动时 obtainOwnedPurchases()
→ 查回已购 productId → 本地写入 PayStore → 功能解锁
```

- **优点**：零服务器、零用户信息收集（合规加分）、官方可信
- **边界**：依赖用户登录华为账号；未登录时只能看本地记录（新机未登录则提示"登录华为账号恢复购买"）
- 这正是"单机版也能恢复购买"的官方方案——**不需要在线记录用户信息**

### 4. 与业务解耦、可移植多 APP
- `pay/` 目录**零 import 业务代码**（只依赖 @kit 系统能力）
- 业务方只调用 `PayGate.isUnlocked(id)` 与 `PayGate.requestUnlock()`（拉起支付）
- 移植到下一个 APP：复制 `pay/` 目录 + 改 `PayConfig.PRODUCTS` 的商品 ID 即可
- 未来换支付平台（安卓 Google Play 等）：新增一个 Adapter，业务零改动

## 四、关键流程

### 购买流程
```
业务点「解锁」→ PayGate.requestUnlock(featureId)
  → 找到商品 → IapAdapter.purchase(productId)
  → 华为收银台 → 回调成功 → PayStore.save(productId)
  → PayGate.isUnlocked → true → 业务刷新 UI
```

### 启动恢复流程
```
App 启动 → PayGate.init()
  → 读本地 PayStore（已购列表）
  → 若 MODE=paid 且 有商品未本地解锁 → IapAdapter.restore()
    → obtainOwnedPurchases → 更新 PayStore
```

### 测试桩
```
MODE=free 或 DebugIap 启用时：isUnlocked 恒 true / purchase 直接成功
→ 开发期可完整走通 UI 流程，无需真实支付
```

## 五、风险与注意

1. **IAP 需真机/沙盒测试**：模拟器通常不支持真实收银台；用 DebugIap 桩先通 UI
2. **商品在 AppGallery Connect 配置**：productId 必须与控制台一致
3. **防篡改**：本地签名校验（轻量）；强需求时再加服务端验签（当前单机版可不做）
4. **30% 平台分成**：定价时考虑
5. **审核合规**：付费功能需在商店描述中声明

## 七、功能价值与收费设计（引擎化路线，2026-08 修订）

> 行业现状：六壬软件普遍"排盘外无功能"，预测师不懂开发、开发者不懂六壬，
> 导致产品停留在"看盘工具"，只能靠直播/预约变现。本项目跨越了知识断层
> （规则数据化 + 引擎化），差异化的核心是把三块内容从"工具提醒"升级为"价值引擎"。

### 7.1 中黄五变经（收费·引擎化）
- **不是卖书**：古籍文本网上可查，直接放原文无价值
- **价值 = 经文变成可交互断课引擎**：
  - 每篇（释己身/释他人/释宗亲/释门类诸人/释五行正形/释主事…）结构化为「类神→象→断语」规则库
  - 与排盘联动：排盘后按课中类神命中，**自动引用经文对应段**（引擎对号入座，非查字典）
  - 年命/身命断：输入年命 → 输出经文级断语
- **卖点**："这部古籍活在你的盘里"，而非"一段能搜到的文字"

### 7.2 抓用神/读象（创新·护城河）
- 现状：候选/节点卡/选句是给预测师看的**半成品**
- 深化方向：
  - **预测师视角**：管辂 507 条 + 类象库 + 毕法 + 盘态 → 整合成**完整断语话术**（起承转合，可直接说给求测者）
  - **用户视角**：断语**生成图卡导出/分享**（盘面+断语成图），自传播
  - **教学视角**：每条断语给**依据链**（为什么这么断：哪条规则/哪个象）——市面软件没有

### 7.3 毕法赋（从"提醒"→"断课教练"）
- 现状：命中"干支皆败"只是标签
- 深化方向：
  - **格局组合**：多格局叠加的综合断（伏吟+任信丁马+催官使者如何统一）
  - **格局→建议**：五层定位的定策层真正落地（宜静守/宜进/防何时）
  - **教学对照**：格局原理 + 真实课例对照，引导走完断课流程
- **定位**：毕法不是"识别器"，是**断课方法论教练**

### 7.4 商业定位（区别于市面软件）
```
免费层（引流）   : 排盘 + 天盘四课三传 + 基础盘态 + 基础读象
买断付费层（壁垒）: 抓用神深度（话术生成+图卡）+ 毕法教练（组合断+建议）
                 + 中黄引擎（经文级断课）
```
> 付费的是"**断课能力**"，不是"看盘权限"——直接翻转"软件只有排盘、收费靠直播"的格局。

### 7.5 功能 ID 门禁（featureId 预埋）
付费功能以 featureId 门禁预留，**改配置不动代码**：
- `yongshen_advanced`：抓用神深度（话术生成+图卡）
- `bifa_coach`：毕法教练（组合断+建议）
- `zhonghuang_engine`：中黄五变经引擎
- 后续新增功能只需在 PayConfig 追加 featureId 与商品映射


## 六、实施步骤（建议顺序）

1. **本期（不动支付）**：建 `pay/` 目录 + PayConfig（MODE=free）+ PayGate + PayStore + DebugIap 桩 → 业务接入 `isUnlocked` 门禁（毕法/读象等处）→ 全功能测试不受影响
2. **下期**：接 HuaweiIap（obtainProductInfo / createPurchaseIntent / obtainOwnedPurchases）→ 真机沙盒验证
3. **上线**：AppGallery 配商品 → MODE 切 paid → 灰度

> 结论：**现在就开始第 1 步**（解耦门禁 + 测试桩），业务零风险，支付能力留好插槽，等你在控制台配好商品再接真支付。
