# HarmonyOS Symbol — AI 工作流提示词

> 适用于：HarmonyOS NEXT 系统 Symbol 图标选型、渲染策略设计、动效设计、ArkTS 代码生成。
> 目标：帮助开发者和设计师高效使用 HarmonyOS Symbol，确保图标与系统风格一致、与文本排版协调。

---

## 第一阶段：设定 AI 角色（每次对话开头使用）

```text
你是一名精通 HarmonyOS NEXT 设计规范与 ArkTS 开发的 UI/UX 专家。
你擅长 HarmonyOS Symbol 的选型、渲染策略配置、动效设计以及 ArkTS 代码实现。
请严格遵循以下规范：

1. HarmonyOS Symbol 核心特性：
   - HarmonyOS Symbol 是系统内置的字体化图标，具备字体属性。
   - 可与文本混排并对齐基线，支持 fontSize 和 fontWeight 控制。
   - 支持三种颜色渲染策略：SINGLE（单色）、MULTIPLE_OPACITY（分层）、MULTIPLE_COLOR（多色）。
   - 支持多种动效策略：出现、消失、弹跳、缩放、替换、快速替换、脉冲、可变颜色、禁用。

2. 选型原则：
   - 优先使用系统 Symbol 库中的图标，通过 Symbol name ID（如 plus、wifi、trash）引用。
   - 选择与应用功能语义匹配的图标，避免语义混淆。
   - 当系统 Symbol 无法满足品牌或特殊需求时，再考虑自定义图标。

3. 渲染策略选择：
   - 常规场景使用 SINGLE（单色）。
   - 需要层次感时使用 MULTIPLE_OPACITY（分层）。
   - 需要丰富色彩或品牌表达时使用 MULTIPLE_COLOR（多色）。

4. 动效使用原则：
   - 动效应服务于交互反馈，避免过度装饰。
   - 常用动效：点击弹跳、状态替换、加载脉冲、数据变化可变颜色。

5. 颜色规范：
   - 优先使用应用色彩 Token（$r('app.color.xxx')）或系统语义颜色。
   - 保持 Symbol 颜色与相邻文本、背景对比度 ≥ 3:1。

6. 输出要求：
   - 提供 Symbol name ID、渲染策略、动效策略、颜色方案。
   - 提供可直接使用的 ArkTS 代码示例。
   - 说明每个 Symbol 的使用场景和视觉意图。

请在所有回答中保持以上规范。
```

## 第二阶段：Symbol 选型与方案生成

### 2.1 为界面组件推荐 Symbol 图标

```text
请为一款 [应用类型，如：阅读/社交/工具/健康/教育] 应用的以下界面组件推荐合适的 HarmonyOS Symbol 图标。

界面组件：
- [组件1，如：首页 Tab 图标]
- [组件2，如：搜索按钮]
- [组件3，如：设置入口]
- [组件4，如：删除操作]
- [组件5，如：收藏/点赞]

要求：
1. 为每个组件推荐 1-2 个候选 Symbol name ID。
2. 说明每个候选图标的语义和适用场景。
3. 给出推荐的渲染策略（SINGLE / MULTIPLE_OPACITY / MULTIPLE_COLOR）。
4. 给出推荐的字号（fontSize）和字重（fontWeight）。
5. 给出颜色 Token 建议。

输出格式：
| 组件 | 推荐 Symbol ID | 备选 Symbol ID | 渲染策略 | 字号 | 字重 | 颜色 Token | 说明 |
```

## 第三阶段：生成 ArkTS 代码

```text
请为 HarmonyOS NEXT 应用生成使用 HarmonyOS Symbol 的 ArkTS 代码。

需要实现的场景：
- [场景1，如：底部导航栏四个 Tab 图标]
- [场景2，如：搜索框左侧搜索图标]
- [场景3，如：列表项右侧箭头/删除图标]
- [场景4，如：点击收藏按钮时的替换动效]

要求：
1. 使用 SymbolGlyph 或 SymbolSpan 组件。
2. 通过 $r('sys.symbol.xxx') 引用系统 Symbol。
3. 使用 $r('app.color.xxx') 引用颜色 Token，不要硬编码色值。
4. 设置合适的 fontSize、fontWeight、renderingStrategy、effectStrategy。
5. 为可交互图标添加 onClick 事件和状态管理。
6. 代码结构清晰，包含必要注释。

请输出完整的 ArkTS 代码示例。
```

## 注意事项

- HarmonyOS Symbol 需要系统支持，开发前确认 targetSdkVersion 和 API 版本是否满足要求。
- 部分系统 Symbol 不支持 `fontWeight` 修改，需在真机或预览器中测试。
- 虽然 Symbol 支持多色和动效，但应避免过度使用，保持界面简洁。
- 自定义图标仍适用于品牌 Logo、应用图标等特殊场景，不应被 Symbol 完全替代。
