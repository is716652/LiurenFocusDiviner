# 沉浸光感设计分析

## 一、核心概念解析

### 1.1 什么是沉浸光感

HarmonyOS 的「沉浸光感」不是单纯添加模糊或阴影，而是一次从「视觉层」到「感知层」的体验升级。它的核心思想是：

> 让界面元素从“实色填充的平面图层”变成“具有光学扩散与动态透光特性的数字介质”。

这意味着：
- 背景与前景之间不再是硬边界，而是像薄雾一样柔和过渡。
- 光线可以在不同层级之间折射、漫反射，产生真实空间感。
- 交互（点击、滑动）会带动光场变化，让操作有“触感”。

### 1.2 沉浸光感解决了什么问题

| 传统界面问题 | 沉浸光感的解决方式 |
|-------------|-------------------|
| 操作栏与内容重叠时显得杂乱 | 用透光材质让操作栏“悬浮”于内容之上，既分离层级又保持通透 |
| 大面积色块占据屏幕，压缩内容空间 | 半透明/模糊材质释放视觉空间，提高屏占比 |
| 交互反馈单调 | 光随手动，按压、滑动都有光影流转 |
| 复杂背景下文字/图标可读性差 | 系统自动反色+材质厚度调节，保证信息清晰 |

## 二、三档强度：用户侧的个性调节

系统向用户提供三档光感强度，作为**全局个性化设置**：

| 档位 | 视觉倾向 | 适用用户 |
|------|----------|----------|
| 强档 | 浓郁、深邃、粒子与空间光效丰富 | 喜欢视觉张力、沉浸氛围的用户 |
| 均衡档（默认） | 通透与对比度平衡，环境光沿边缘流转 | 大多数用户，日常通用 |
| 弱档 | 轻盈克制、高对比度、信息清晰锐利 | 偏好简洁、对可读性要求高的用户 |

**对开发者的意义**：
- 不需要为三档分别写代码。
- 只需指定材质样式（`ULTRA_THIN` ~ `ULTRA_THICK`），系统会根据用户选择自动映射渲染参数。
- 设计稿中应预留三档强度的视觉差异空间，但交付开发时以一套规范为准。

## 三、五档材质：设计与开发的共同语言

`ImmersiveStyle` 提供 5 个层级，从薄到厚对应不同的信息层级与场景：

| 枚举 | 透明度 | 模糊度 | 典型使用场景 |
|------|--------|--------|-------------|
| `ULTRA_THIN` | 最高 | 最弱 | 顶部悬浮工具栏、导航栏背景 |
| `THIN` | 高 | 弱 | 底部悬浮操作区、搜索框 |
| `REGULAR` | 中等 | 中等 | 通用卡片、按钮 |
| `THICK` | 低 | 强 | 菜单、提示气泡、弹出面板 |
| `ULTRA_THICK` | 最低 | 最强 | 半模态页面、弹窗、对话框 |

### 3.1 材质选择逻辑

选择材质档位时，建议按以下优先级判断：

1. **是否与复杂背景重叠？** 是 → 考虑 `THIN` 及以上。
2. **占据屏幕面积是否较大？** 是 → 倾向于 `THICK` / `ULTRA_THICK`。
3. **是否需要保持背景内容可见？** 是 → 倾向于 `ULTRA_THIN` / `THIN`。
4. **是否是临时弹出的覆盖层？** 是 → 倾向于 `THICK` / `ULTRA_THICK`。

### 3.2 常见组件映射建议

| 组件 | 推荐材质 | 原因 |
|------|----------|------|
| 顶部导航栏 | `ULTRA_THIN` + 渐变模糊 | 延展顶部空间，不遮挡内容 |
| 底部 Tab 栏/操作栏 | `THIN` + 渐变蒙层 | 稳定操作区，轻度分离 |
| 搜索框 | `THIN` / `REGULAR` | 需要一定存在感但不过重 |
| 按钮 | `REGULAR` / `ULTRA_THIN` | 根据背景复杂度选择 |
| 菜单/上下文菜单 | `THICK` | 内容可读性优先 |
| Toast | `THIN` | 轻量提示，不抢眼 |
| Popup / Tips | `THIN` | 临时气泡，保持轻盈 |
| 底部 Sheet | `ULTRA_THICK` | 大面积覆盖，需强对比 |
| 弹窗/对话框 | `ULTRA_THICK` | 强焦点，确保内容清晰 |

## 四、设计原则

### 4.1 不要为了光感而光感

沉浸光感适合处理「操作元素可能与内容重叠」的场景。如果页面本身层级简单、背景单一，强行使用厚重材质反而会显得冗余。

### 4.2 保持信息层级清晰

光感是辅助层级表达的手段，不能替代层级关系。设计时应确保：
- 主要内容始终具有最高视觉优先级。
- 操作组件通过材质厚度与背景自然分离。
- 文字、图标在材质上保持足够对比度。

### 4.3 尊重系统个性化设置

用户选择的光感强度会影响最终渲染效果。设计稿应：
- 以均衡档为基准出图。
- 在关键场景（如弱档）检查文字可读性。
- 避免依赖特定光影特效传达核心信息。

### 4.4 交互反馈要自然

开启 `interactive` 和 `lightEffect` 时，光影变化应跟随手势，避免过度夸张。目标是“增强触感”，而非“喧宾夺主”。

## 五、对现有项目的迁移建议

对于已经使用纯色背景、阴影或手动模糊的组件，可以按以下步骤迁移：

1. **识别重叠场景**：找出顶部悬浮、底部悬浮、弹出层、半模态等组件。
2. **替换背景实现**：将 `backgroundColor` 或 `backgroundBlurStyle` 替换为 `systemMaterial(new uiMaterial.ImmersiveMaterial({ style: ... }))`。
3. **移除冗余阴影/边框**：系统材质会自动处理背景色、边框、阴影和材质滤镜。
4. **验证三档强度**：在设备上切换强/均衡/弱三档，检查可读性与视觉一致性。
5. **处理反色需求**：对于固定在复杂背景上的文字，开启 `colorInvert: true` 并验证效果。

## 六、设计交付清单

向开发交付沉浸光感相关设计时，建议包含：

- [ ] 各场景的材质档位标注（`ULTRA_THIN` / `THIN` / `REGULAR` / `THICK` / `ULTRA_THICK`）
- [ ] 是否需要 `interactive` 交互形变
- [ ] 是否需要 `lightEffect` 光感交互反馈
- [ ] 是否需要 `colorInvert` 自动反色
- [ ] 三档强度下的效果图（至少均衡档）
- [ ] 与背景内容重叠时的边界处理说明
