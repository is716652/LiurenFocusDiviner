# HarmonyOS NEXT 色彩设计 — AI 可直接使用的提示词

> 基于华为官方文档《色彩》提炼，用于指导 AI 生成/评估 HarmonyOS NEXT 应用的色彩设计或代码。

---

## 通用系统提示词（放在对话开头）

```text
你是一名熟悉 HarmonyOS NEXT 设计规范的 UI/UX 设计专家与鸿蒙开发顾问。
请严格遵循以下 HarmonyOS NEXT 色彩设计原则：

1. 色彩设计需强调品牌色特征和系统色彩对比关系。
2. 系统色调以“宇宙蓝”和“雪域灰”为基础，象征苍穹与大地，整体风格应干净、和谐、纯净。
3. 色彩分层用于构建不同使用场景的对比关系，每个颜色需有明确用途和层级。
4. 必须保障最小 3:1 的对比度，确保可读性。
5. 使用 Design Token 管理系统色彩，分为基础 Token、语义 Token、控件 Token 三层：
   - 基础 Token：primary、on_primary、brand、container、background 等
   - 语义 Token：文本类、图标类、组件类、交互事件类
   - 控件 Token：指定控件内唯一元素的参数，不可复用
6. 浅色/深色模式使用相同 Token 名称，但可对应不同色值。
7. 应用自定义品牌色时，需让用户能识别当前应用并理解关键事件。
8. 避免硬编码色值，优先使用语义化 Token 和资源引用。

请在所有回答中保持以上规范。
```

## 场景 1：生成 HarmonyOS NEXT 应用配色方案

```text
请为一款 [应用类型，例如：阅读类/社交类/工具类] 的 HarmonyOS NEXT 应用设计一套配色方案。

要求：
- 定义应用品牌色，并说明其象征意义和适用场景。
- 基于 HarmonyOS NEXT 色彩系统，列出基础 Token 及其色值（包含浅色模式与深色模式）。
- 为文本、图标、按钮、卡片、背景、分割线等元素定义语义 Token。
- 说明每个颜色在不同层级中的对比关系。
- 确保所有文本与背景组合满足最小 3:1 对比度。
- 输出格式为表格，包含：Token 名称、用途、浅色色值、深色色值、使用场景。
```

## 场景 2：生成 ArkTS / ArkUI 色彩资源代码

```text
请为 HarmonyOS NEXT 应用生成 ArkTS / ArkUI 的色彩资源定义。

要求：
- 使用 resources/base/theme.json 和 resources/dark/theme.json 分别定义浅色和深色模式色值。
- 颜色资源名称使用语义化命名，参考 HarmonyOS Token 规范，例如：
  - 基础层：primary、on_primary、brand、container、background、surface
  - 语义层：text_primary、text_secondary、icon_default、divider、button_primary_background
  - 控件层：custom_card_title_text、custom_list_item_background
- 浅色/深色模式下资源名称保持一致，仅色值不同。
- 提供一段示例 ArkTS 代码，展示如何通过 $r('app.color.xxx') 引用这些颜色。
- 不要硬编码任何 #RRGGBB 色值到组件代码中。
```

- ...

要求：
1. 计算每组颜色对比度。
2. 判断是否满足 HarmonyOS NEXT 最小 3:1 标准。
3. 对不满足的组合，给出调整后的色值建议。
4. 额外考虑色盲/色弱用户是否能区分关键状态（如错误、成功、警告）。

## 场景 9：设计启动页 / 应用内背景

```text
请为 [应用名称] 设计 HarmonyOS NEXT 风格的启动页背景和应用内主背景。

设计要求：
1. 启动页背景需突出品牌，同时让启动页 Logo 清晰可辨。
2. 应用内主背景需支持浅色/深色模式切换。
3. 背景可使用 subtle 纹理、渐变或留白，但不得干扰前景内容阅读。
4. 背景色必须使用 Token 命名，如 background、surface、container。
5. 背景与前景文本对比度 ≥ 3:1。
6. 考虑不同屏幕尺寸和折叠屏设备的适配。

请输出：
- 启动页背景方案（含颜色 Token、渐变/纹理说明）
- 应用内主背景方案（浅色/深色）
- 背景与前景内容的对比度分析
- 注意事项（如避免在背景中使用大面积高饱和色）
```
