## 一、网页核心内容概述

该页面是 **HarmonyOS NEXT 官方 UX 设计规范** 中关于「应用图标」的章节，主要阐述应用图标的设计理念、设计原则和技术实现规范。

与单纯的「Logo 设计」不同，HarmonyOS NEXT 应用图标需要同时满足：
- **视觉设计层面**：简洁、达意、有情感
- **技术实现层面**：分层图标、1024×1024 正方形 PNG、正确配置
- **审核合规层面**：避免单层图标、module 覆盖、工具版本过低等问题

## 二、设计原则深度分析

### 2.1 简洁优雅

| 维度 | 分析 |
|---|---|
| **形式** | 图形元素尽量精简，避免过多装饰性细节 |
| **线条** | 轮廓线条流畅、优雅，符合现代扁平/轻拟物审美 |
| **色彩** | 控制色板数量，建议 1-2 种主色 + 1 种辅助色 |
| **价值** | 在桌面众多图标中保持视觉清晰，不被细节淹没 |

### 2.2 极速达意

| 维度 | 分析 |
|---|---|
| **语义** | 图形应直接关联应用核心功能或服务 |
| **识别性** | 即使在小尺寸（如通知栏 24dp）下也能被识别 |
| **易读性** | 避免抽象过度，用户能在一秒内理解应用属性 |
| **案例** | 天气应用使用温度/云朵符号，计算器应用使用数字/运算符号 |

### 2.3 情感表达

| 维度 | 分析 |
|---|---|
| **品牌情感** | 通过色彩、图形风格传递品牌调性（如科技、温暖、专业、活力） |
| **色彩心理** | 蓝色传递信任，橙色传递活力，绿色传递自然/健康 |
| **图形个性** | 圆角、有机曲线传递友好；直线、几何图形传递专业/科技感 |
| **价值** | 在同质化应用中脱颖而出，建立用户情感连接 |

## 三、技术规范分析

### 3.1 为什么必须分层

HarmonyOS 支持图标的自适应形状和动态效果（如按压缩放、动效等），单层 PNG 无法满足这些系统级能力。分层图标的优势：

| 优势 | 说明 |
|---|---|
| 自适应形状 | 系统可根据主题或设备自动调整图标外形 |
| 动态效果 | 支持前景与背景的相对运动/缩放 |
| 一致性 | 与系统原生图标保持统一的视觉语言 |
| 可维护性 | 前景和背景可独立更新 |

### 3.2 分层图标结构

```
AppScope/resources/base/media/
├── foreground.png          # 前景：Logo 主体 / 核心图形
├── background.png          # 背景：底色 / 纹理 / 渐变
└── layered_image.json      # 关联配置
```

`layered_image.json` 示例：

```json
{
  "layered-image": {
    "background": "$media:background",
    "foreground": "$media:foreground"
  }
}
```

### 3.3 配置优先级问题

| 配置文件 | 优先级 | 说明 |
|---|---|---|
| `entry/src/main/module.json5` | 高 | 若配置 `icon`/`label`，会覆盖 AppScope 配置 |
| `AppScope/app.json5` | 低 | 应用级默认配置 |

**建议**：
- 单入口应用：在 `AppScope/app.json5` 中配置图标，删除或避免在 `module.json5` 中重复配置
- 多入口应用：确保各 `module.json5` 的图标配置正确且一致

## 四、与鸿蒙开发的关系

### 4.1 对开发者的直接意义

| 方面 | 关系说明 |
|---|---|
| **应用识别** | 图标是用户找到应用的第一入口，直接影响点击率和品牌认知。 |
| **审核通过** | 不符合分层规范的图标会导致上架审核被驳回。 |
| **系统一致性** | 遵循规范可与系统原生图标保持和谐，提升整体体验。 |
| **动态效果** | 分层图标可支持系统的动效和自适应能力。 |

### 4.2 在 ArkTS / ArkUI 开发中的体现

- 图标资源通常放置在 `AppScope/resources/base/media/`
- 通过 `app.json5` 中的 `"icon": "$media:layered_image"` 引用
- 应用名称通过 `"label": "$string:app_name"` 引用
- 无需在 ArkTS 代码中直接处理图标，由系统自动渲染

## 五、启示与建议

### 5.1 设计启示

1. **少即是多**
   - 避免复杂场景、过多元素、细碎装饰。
   - 一个核心图形 + 品牌色即可构成优秀图标。

2. **功能即图形**
   - 图标图形应能直接唤起用户对应用功能的联想。
   - 不要 purely abstract（纯抽象），除非品牌已足够强。

3. **色彩克制**
   - 主色 1-2 种，辅助色 1 种。
   - 背景色与前景色对比度足够，确保可识别。

4. **安全区意识**
   - 核心图形位于安全区内，避免被系统裁切或动效影响。
   - 边缘留足安全边距。

5. **多尺度测试**
   - 设计完成后需检查 1024px、216px、48px、24px 等尺寸下的效果。
   - 小尺寸下图标依然清晰可辨。

### 5.2 开发启示

1. **严格分层**
   - 包体内图标必须提供 foreground.png 和 background.png。
   - 两者均为 1024×1024 正方形 PNG。

2. **正确配置**
   - 使用 `layered_image.json` 关联两层。
   - 在 `app.json5` 中引用 `$media:layered_image`。
   - 检查 `module.json5` 是否错误覆盖了 `app.json5`。

3. **工具版本**
   - 使用 DevEco Studio 5.0.5.315 或更高版本。
   - 可使用 `File -> New -> Image Asset` 辅助生成。

4. **素材分离**
   - 包体内图标（分层）与商店展示图标（可合成）分开准备。
   - 商店图标可使用 216×216 或 1024×1024 的 PNG/WEBP。

5. **版本控制**
   - 保留 SVG/AI/Figma 源文件，便于后续迭代。
   - 生成脚本（如 Python/PIL）可纳入项目，实现图标自动化生成。

### 5.3 项目实践建议

| 场景 | 建议 |
|---|---|
| 新应用设计图标 | 先确定品牌色和核心图形，再设计分层前景/背景。 |
| 已有 Logo 迁移 | 将 Logo 主体提取为前景，设计纯色/渐变背景。 |
| 多主题适配 | 可准备多组背景，但需保持前景一致。 |
| 自动化生成 | 使用 Python/PIL 脚本按规范生成 1024×1024 分层 PNG。 |
| 上架前检查 | 对照审查自查清单，确认分层、尺寸、配置、工具版本。 |

## 六、设计 → 开发交付流程

```
1. 概念设计
   ↓ 确定品牌关键词、核心图形、色彩方案
2. 分层设计
   ↓ 设计 foreground.png（主体）和 background.png（底色）
3. 技术配置
   ↓ 编写 layered_image.json，配置 app.json5 / module.json5
4. 资源生成
   ↓ 导出 1024×1024 PNG，必要时用脚本批量生成
5. 验证测试
   ↓ 编译安装，检查桌面显示效果
6. 上架准备
   ↓ 准备商店展示图标（216×216 或 1024×1024 PNG/WEBP）
```

## 七、总结

HarmonyOS NEXT 应用图标设计规范包含「设计原则」和「技术实现」两个维度：

- **设计原则**强调简洁优雅、极速达意、情感表达，帮助应用在众多图标中脱颖而出。
- **技术规范**要求分层图标、1024×1024 正方形 PNG、正确配置，确保审核通过和系统一致性。

对于开发者和设计师而言，理解并遵循这些规范可以：

- 提升应用的品牌识别度和用户点击率。
- 避免因图标不合规导致的上架审核失败。
- 与 HarmonyOS 系统视觉语言保持一致。
- 通过自动化脚本提升图标生成和维护效率。
