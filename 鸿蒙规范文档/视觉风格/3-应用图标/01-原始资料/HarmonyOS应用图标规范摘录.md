## 一、应用图标设计的核心

**鸿蒙（HarmonyOS NEXT）App 的 logo 不能直接提交一个普通 PNG 图片**。它需要满足一套专门的分层图标规范，否则会在上架审核时被驳回。

应用图标设计的核心是 **简洁、高效和品牌识别度**。

一个好的图标可以：
- 准确传达应用相关信息
- 帮助用户快速定位你的应用

HarmonyOS 图标设计旨在回归本源，通过现代化的语义表达，准确传达功能、服务和品牌：
- **视觉上**：兼顾美观性和识别性
- **形式上**：兼收并蓄，和而不同

## 二、HarmonyOS 应用图标设计原则

### 2.1 简洁优雅

- 元素图标简洁
- 线条表现优雅
- 传递设计美学

### 2.2 极速达意

- 图标图形准确传达其功能、服务和品牌
- 具有易读性和识别性
- 用户一眼即可理解应用属性

### 2.3 情感表达

- 通过图形和色彩概括表达情感
- 传达品牌视觉形象
- 在简洁中体现品牌个性

## 三、HarmonyOS NEXT 分层图标技术要求

鸿蒙系统支持图标的自适应形状和动态效果，因此应用图标必须由 **前景图（Foreground）** 和 **背景图（Background）** 两层叠加构成。

### 3.1 图片规格

| 项目 | 要求 |
|---|---|
| **尺寸** | 必须是 `1024px × 1024px` 的正方形 PNG 图片 |
| **形状** | 资源本身必须是正方形，不要自行裁切圆角或添加内间距 |
| **遮罩** | 系统会根据不同场景自动生成对应的遮罩效果 |
| **核心图形** | 应位于安全区内，避免被系统裁切或动态效果影响 |

### 3.2 配置方式

- 通过 `layered_image.json` 文件将前景图和背景图关联起来（推荐方式）
- 旧版规范中也可能使用 `start_icon.json` 进行关联
- 在 `AppScope/app.json5` 中引用分层图标资源
- 注意：`module.json5` 中的图标配置优先级高于 `app.json5`，需谨慎处理

```json
// AppScope/resources/base/media/layered_image.json
{
  "layered-image": {
    "background": "$media:background",
    "foreground": "$media:foreground"
  }
}
```

### 3.3 开发工具要求

- 建议使用 **DevEco Studio 5.0.5.315 或更高版本** 进行图标处理和打包
- 可通过 `File -> New -> Image Asset` 工具生成规范的图标资源

## 四、包体内图标 vs 商店展示图标

| 类型 | 尺寸 | 格式 | 是否分层 | 用途 |
|---|---|---|---|---|
| **包体内图标** | 1024px × 1024px | PNG | 必须分层（前景 + 背景） | 应用安装后在桌面、系统设置等位置显示 |
| **商店展示图标** | 216×216px 或 1024×1024px | PNG / WEBP | 无需强制分层 | AppGallery Connect 后台上传，用于应用商店展示 |

## 五、常见审核失败原因及解决方案

如果你在提交时遇到「**未配置图标的前景图和后景图**」的提示，通常有以下几种可能及对应的解决办法：

| 问题 | 原因 | 解决方案 |
|---|---|---|
| **使用了单层图标** | 只上传了一张普通图片，而非分层资源 | 按要求制作前景图和背景图，并使用 DevEco Studio 的 `File -> New -> Image Asset` 工具生成规范的图标资源 |
| **配置被错误覆盖** | `module.json5` 中的图标配置优先级高于 `app.json5` | 如果不需要多入口图标，检查并删除 `module.json5` 中的 `icon` 和 `label` 配置，以减少错误几率 |
| **开发工具版本过低** | 未使用推荐版本 | 使用 **DevEco Studio 5.0.5.315 或更高版本** 进行图标处理和打包 |
| **尺寸或格式不符合规范** | 非 1024×1024 正方形 PNG，或自行裁切了圆角 | 重新导出符合规范的正方形 PNG 资源 |

## 六、HarmonyOS 标识使用规范

如果希望在图标中使用 HarmonyOS 的官方标识：
- 必须按照设计规范
- 以单色形式放置在图标右下角固定位置
- 不可随意修改大小、颜色或位置
