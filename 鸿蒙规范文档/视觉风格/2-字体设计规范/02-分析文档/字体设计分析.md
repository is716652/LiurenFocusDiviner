## 一、网页核心内容概述

`字体` 章节主要介绍 HarmonyOS 的系统默认字体 **HarmonyOS Sans** 的设计理念、技术特点和适用场景。

`字体排印` 章节则进一步定义了在操作系统中对文字的布局和呈现方式，包括官方推荐的文字比例系统（Type Scale）、排版体验要求以及多设备适配规范。

两者结合，构成 HarmonyOS NEXT 完整的字体设计规范体系。

## 二、HarmonyOS Sans 核心特征

### 2.1 字体类型

- **无衬线字体（Sans-serif）**
- 无额外装饰笔画
- 结构简洁清晰
- 专为屏幕显示优化

### 2.2 设计目标

| 目标 | 说明 |
|---|---|
| **良好的屏幕显示效果** | 优化字形灰度，适合各类屏幕分辨率 |
| **高阅读效率** | 结构清晰，减少视觉负担 |
| **多端一致体验** | 在手机、平板、车机、手表等不同设备上保持统一 |
| **多语言支持** | 支持中文、拉丁、希腊、西里尔、阿拉伯等语系 |

### 2.3 字体设计特点

| 特点 | 说明 |
|---|---|
| **字面灰度适中** | 字体黑白分布均匀，视觉上不轻不重 |
| **字面率更大** | 相同字号下显得更大、更易读 |
| **底部收笔简洁** | 减少装饰性细节，提升屏幕显示清晰度 |
| **多语言混排基线协调** | 中英文/多语言混排时视觉对齐更自然 |
| **人体工学参数系统** | 字号、字重、行高等参数经过系统化设计 |
| **可变字体能力** | 支持字重等属性的连续变化，适配不同场景 |

## 三、HarmonyOS NEXT 字体排印体系

### 3.1 排版体验五要求

| 要求 | 对开发者的启示 |
|---|---|
| 最小可读字号 | 正文避免小于 12vp，辅助信息避免小于 10vp |
| 色彩和对比度 | 文本颜色必须使用 Token，确保与背景对比度 ≥ 3:1 |
| 一致的字体风格 | 全应用统一使用 HarmonyOS Sans，不随意切换字重 |
| 简洁的样式表达信息 | 避免过多层级，建议控制在 5 大类 × 3 子级以内 |
| 支持系统大字体 | 使用 `vp`/`fp` 单位，避免固定 px，支持无障碍放大 |

### 3.2 官方文字比例系统

官方将 UI 文本分为 **Display / Title / Subtitle / Body / Caption** 五大类，每类再分 L / M / S 三个子级。

#### 推荐尺寸与字重（Phone 端）

| 场景类别 | 层级 Token | 字重 | 尺寸 |
|---|---|---|---|
| 展示性文本 Display | Display_L / M / S | Light | 56 / 48 / 38 vp |
| 标题文本 Title | Title_L / M / S | Bold | 30 / 24 / 20 vp |
| 副标题文本 Subtitle | Subtitle_L / M / S | Medium | 18 / 16 / 14 vp |
| 正文文本 Body | Body_L / M / S | Medium / Regular | 16 / 14 / 12 vp |
| 说明文本 Caption | Caption_L / M / S | Medium | 12 / 10 / - vp |

#### Token 命名规律

```
{类别}_{子级}
```

例如：`Title_L`、`Body_M`、`Caption_S`

### 3.3 多设备适配

同一 Token 在不同设备上对应不同尺寸：

| Token | phone | PC | watch |
|---|---|---|---|
| Title_L | 30 vp | 28 vp | 30 vp |
| Body_M | 14 vp | 14 vp | 14 vp |
| Caption_M | 10 vp | 9 vp | 10 vp |

> 在 ArkTS 开发中，可以通过 `vp`/`fp` 单位让系统自动适配不同设备密度。若需要更精细的多设备尺寸，可结合 `mediaQuery` 或 `breakpoint` 实现。

### 3.4 字重与层级的对应关系

| 字重 | 英文名称 | 数值参考 | 适用层级 |
|---|---|---|---|
| Light | 细体 | 300 | Display |
| Regular | 常规 | 400 | Body |
| Medium | 中等 | 500 | Subtitle / Body_L / Caption |
| Bold | 粗体 | 700 | Title |

> HarmonyOS Sans 支持可变字体，实际开发中：
> - Light 字重使用 `FontWeight.Lighter`
> - Regular 字重使用 `FontWeight.Regular` 或 `FontWeight.Normal`
> - Medium 字重使用 `FontWeight.Medium`
> - Bold 字重使用 `FontWeight.Bold`

## 四、与鸿蒙开发的关系

### 4.1 对开发者的直接意义

| 方面 | 关系说明 |
|---|---|
| **默认字体** | HarmonyOS Sans 是系统默认字体，开发者通常无需额外引入字体文件。 |
| **跨设备一致性** | 使用系统字体可保证在手机、平板、车机、手表等设备上显示一致。 |
| **多语言适配** | 系统字体已支持多语系，开发者无需为不同语言单独配置字体。 |
| **可读性保障** | 遵循官方字号、字重规范，可确保良好的阅读体验。 |
| **性能优化** | 避免引入第三方字体文件，减少包体积和加载时间。 |

### 4.2 在 ArkTS / ArkUI 开发中的体现

- 默认情况下，文本组件（`Text`）会自动使用 HarmonyOS Sans。
- 可通过 `fontFamily`、`fontSize`、`fontWeight`、`lineHeight` 等属性控制字体样式。
- **官方推荐使用 `vp`/`fp` 作为字号单位**，实现多设备适配和无障碍大字体支持。
- 建议优先使用系统推荐的文字比例系统，保持与系统一致的阅读体验。
- 如需自定义字体，应谨慎评估包体积和版权风险。

## 五、启示与建议

### 5.1 设计启示

1. **优先使用系统字体**
   - HarmonyOS Sans 经过专门优化，是最佳选择。

2. **遵循官方文字比例系统**
   - 使用 Display / Title / Subtitle / Body / Caption 五大类及其 L / M / S 子级。
   - 避免随意设置字号，确保全应用层级一致。

3. **重视字重对比**
   - 通过字重（Light / Regular / Medium / Bold）区分信息层级，而非仅靠颜色。

4. **保证行高与段落间距**
   - 合理的行高和段落间距能提升长文本阅读舒适度。
   - 建议：标题行高 ≈ 字号 × 1.3，正文行高 ≈ 字号 × 1.5 ~ 1.75。

5. **考虑多语言混排**
   - 中英文混排时，注意基线对齐和视觉平衡。

6. **支持无障碍大字体**
   - 使用 `vp`/`fp` 单位，避免固定 px，确保系统大字体模式下仍可正常显示。

### 5.2 开发启示

1. **不要硬编码字体**
   - 除非有特殊品牌需求，否则不要指定自定义字体族。

2. **使用语义化文本样式 Token**
   - 建议定义文本样式 Token，如 `text_display_l`、`text_title_m`、`text_body`、`text_caption` 等，便于统一维护。
   - 字号、行高通过 `float.json` 管理，字重通过 ArkTS 常量管理。

3. **颜色与字体 Token 分离**
   - 颜色使用 `$r('app.color.xxx')`。
   - 字号/行高使用 `$r('app.float.xxx')`。
   - 文本样式常量组合颜色和字体属性，实现「样式 = 字体 + 颜色」的解耦。

4. **适配不同设备**
   - 在手机、折叠屏、平板等设备上，使用 `vp`/`fp` 单位自动适配。
   - 如需更精细控制，可结合断点系统为不同屏幕尺寸设置不同 Token。

5. **关注无障碍**
   - 确保正文文字足够大、对比度足够高，满足视力障碍用户需求。
   - 正文建议使用 Body_L / Body_M（14 ~ 16 vp），避免使用小于 Body_S（12 vp）的文本承载核心信息。

### 5.3 项目实践建议

| 场景 | 建议 |
|---|---|
| 新建鸿蒙应用 | 默认使用 HarmonyOS Sans，定义一套符合官方文字比例系统的文本样式 Token。 |
| 设置大标题/欢迎标题 | 使用 `Display_*` 或 `Title_L`，Bold / Light 字重。 |
| 设置页面/卡片标题 | 使用 `Title_M` / `Title_S`，Bold 字重。 |
| 设置副标题 | 使用 `Subtitle_*`，Medium 字重。 |
| 设置正文 | 使用 `Body_L` / `Body_M`，Regular / Medium 字重。 |
| 设置辅助文字 | 使用 `Caption_*`，Medium 字重。 |
| 多语言应用 | 依赖系统字体多语言支持，无需额外配置。 |

## 六、推荐的 ArkTS Token 映射

基于官方文字比例系统，推荐的 Token 命名如下：

| 官方 Token | 推荐 float.json Token（phone） | 推荐值 | ArkTS 字重 |
|---|---|---|---|
| Display_L | `text_display_l_size` | 56vp | FontWeight.Lighter |
| Display_M | `text_display_m_size` | 48vp | FontWeight.Lighter |
| Display_S | `text_display_s_size` | 38vp | FontWeight.Lighter |
| Title_L | `text_title_l_size` | 30vp | FontWeight.Bold |
| Title_M | `text_title_m_size` | 24vp | FontWeight.Bold |
| Title_S | `text_title_s_size` | 20vp | FontWeight.Bold |
| Subtitle_L | `text_subtitle_l_size` | 18vp | FontWeight.Medium |
| Subtitle_M | `text_subtitle_m_size` | 16vp | FontWeight.Medium |
| Subtitle_S | `text_subtitle_s_size` | 14vp | FontWeight.Medium |
| Body_L | `text_body_l_size` | 16vp | FontWeight.Medium |
| Body_M | `text_body_m_size` | 14vp | FontWeight.Regular |
| Body_S | `text_body_s_size` | 12vp | FontWeight.Regular |
| Caption_L | `text_caption_l_size` | 12vp | FontWeight.Medium |
| Caption_M | `text_caption_m_size` | 10vp | FontWeight.Medium |

对应的行高 Token 可命名为 `text_title_l_line_height`、`text_body_m_line_height` 等。

## 七、总结

HarmonyOS Sans 是 HarmonyOS NEXT 的核心视觉资产之一，而官方字体排印规范则提供了完整的文字比例系统。两者结合，可以帮助开发者：

- 保证应用在不同设备上的视觉一致性。
- 提升文本可读性和用户阅读效率。
- 减少自定义字体带来的性能和版权风险。
- 建立规范的文本样式体系，提升设计与开发协作效率。
- 支持系统大字体等无障碍特性。

对于鸿蒙开发者而言，建议：

1. 默认使用 HarmonyOS Sans。
2. 遵循官方 Display / Title / Subtitle / Body / Caption 文字比例系统。
3. 使用 `vp`/`fp` 单位定义字号，支持多设备与无障碍适配。
4. 通过 `float.json` + ArkTS 样式常量建立语义化文本样式 Token。
5. 颜色与字体样式解耦，颜色使用 `color.json` Token，字体使用 `float.json` Token。
