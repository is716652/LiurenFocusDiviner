# 圆角参数设计分析

## 一、核心概念解析

### 1.1 什么是圆角参数

圆角参数是设计系统中对矩形边角进行圆弧化处理的一组固定数值规范。它不是一个单纯的美学选择，而是影响：

- **视觉心理**：圆角比直角更柔和、友好，降低压迫感。
- **层级表达**：圆角半径大小与元素层级正相关。
- **触控体验**：圆润的边角更容易被识别为可点击/可交互区域。
- **品牌调性**：统一圆角风格能传递现代、专业、亲和的产品气质。

### 1.2 圆角参数解决了什么问题

| 问题 | 圆角参数的作用 |
|------|---------------|
| 界面过于生硬、机械 | 通过圆角柔化边缘，增加亲和力 |
| 控件层级不明确 | 用不同半径区分元素层级 |
| 同类型控件风格不统一 | 设定固定半径，保证一致性 |
| 触控区域识别困难 | 圆润边角暗示可点击性 |

## 二、HarmonyOS 通用圆角体系

HarmonyOS 提供了 5 档通用圆角参数，形成一个完整的层级梯度：

| 半径 | 层级定位 | 典型应用 |
|------|----------|----------|
| 4vp | 超小 | 标签、角标、状态标识、迷你图标背景 |
| 8vp | 小 | 图片、图标、小型卡片、缩略图 |
| 16vp | 中 | 通知卡片、内容容器、列表卡片 |
| 20vp | 大 | 按钮、菜单、底部操作栏、搜索框 |
| 32vp | 超大 | 半模态、弹出框、对话框、大面积覆盖层 |

### 2.1 选择逻辑

选择圆角半径时，建议按以下顺序判断：

1. **元素面积大小**：面积越大，通常圆角越大。
2. **层级高度**：越靠近顶层的覆盖元素，圆角越大。
3. **功能属性**：操作类控件（按钮）通常比展示类（图片）圆角大。
4. **同层一致性**：同类型组件必须使用相同圆角。

## 三、两条核心设计原则

### 3.1 同层统一

同一功能层级、同一类型的控件或容器，必须采用一致的圆角半径。

**示例**：
- 所有列表卡片都用 16vp
- 所有按钮都用 20vp（或统一用 24vp，但不要混用）
- 所有标签都用 4vp

**反例**：
- 两个并排的卡片，一个 12vp、一个 16vp
- 同类按钮有的圆角有的直角

### 3.2 层级正相关

圆角半径与元素层级呈正相关：层级越高，圆角越大。

**示例层级关系**：

```
页面底层背景：0vp（直角或无圆角）
  ↓
内容卡片：16vp
  ↓
按钮/菜单：20vp
  ↓
半模态/弹窗：32vp
```

这种梯度让用户一眼就能感知到哪个元素浮在最上面。

## 四、各场景详细映射

### 4.1 4vp：标签与角标

适用于辅助性、装饰性、小尺寸元素。

- 标签（Tag）
- 角标（Badge）
- 状态点/状态标识
- 小型图标背景

### 4.2 8vp：图片与图标

适用于需要轻微柔化但不宜过度圆润的元素。

- 头像
- 图片/视频缩略图
- 图标容器
- 小型信息卡片

### 4.3 16vp：内容卡片

适用于信息承载型容器。

- 通知卡片
- 列表项卡片
- 功能模块卡片
- 内容容器

### 4.4 20vp：按钮与菜单

适用于操作控件。

- 主按钮/次按钮
- 菜单项
- 搜索框
- 底部操作栏

### 4.5 32vp：半模态与弹窗

适用于大面积覆盖层和顶层容器。

- 半模态页面（Sheet）
- 对话框/弹窗
- 底部弹出面板
- 悬浮大卡片

## 五、常见误区

| 误区 | 正确做法 |
|------|----------|
| 所有组件都用同一个圆角 | 按层级和功能选择不同半径 |
| 圆角越大越好 | 超大圆角只用于顶层大容器，小元素用大会显得臃肿 |
| 同类型组件圆角不一致 | 建立 token 表，强制统一 |
| 圆角完全凭感觉 | 使用系统固定档位（4/8/16/20/32vp），不随意取中间值 |
| 忽略内嵌元素的圆角关系 | 卡片内部图片/按钮的圆角应小于卡片本身 |

向开发交付圆角相关设计时，建议包含：

- [ ] 各组件类型的圆角半径标注
- [ ] 圆角 token 命名规范
- [ ] 同类型组件圆角一致性检查
- [ ] 嵌套关系说明（如卡片内图片圆角小于卡片圆角）
- [ ] 特殊场景（如全圆角按钮、异形卡片）的标注
