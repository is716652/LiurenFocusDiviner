也无 `layoutWeight`，`Blank()` 又抢占剩余宽度，于是长文案（毕法展开的五层：定性/定象/定时/定策/定级）
顶出父容器右边界；`textAlign(End)` 使正文右对齐，"看着没左对齐"。短值（如「旬空 / 无」）看不出问题，
所以只在长文案处暴露。

修法：
- `InfoRow` 增加 `stack` 模式（`stack: true` = 标签在上、值在下、**左对齐**），毕法五层改用它；
  容器 `Column` 显式 `.alignItems(HorizontalAlign.Start)`（ArkUI 的 Column 默认居中）。
- 默认模式（短值，如盘态的旬空/旺衰）保持"标签左、值右"，但值改 `.layoutWeight(1)` 约束宽度，
  不再用 `Blank()` 抢宽度。
- 顺带排查同类隐患（同一个 Row 里有 `Blank()`、并列 `Text` 却是数据驱动且无宽度约束）：
  共 12 处，其中 7 处（课体/三传标题、用神节点、用神提示、毕法法名、案例三传标题等）加 `.layoutWeight(1)`（末位元素另加 `.textAlign(TextAlign.End)` 保持贴右）；
  5 处长度确实有界的（地支+时、返回文案、日期串、旬空+旺衰、收起/展开）加 `layout-ok: 理由` 标记放行。

**新增常驻门禁** `_tests/_test_ui_layout.js`（判据与修法见 `Agent.md` §9「UI 排版门禁」）：
扫主版 + 免费版全部 UI 文件（96 个），违规即 exit 1。修后 **违规 0、豁免 5 处 × 2 版本**。

**验证结论（2026-09-12，用户真机确认）**：装上述最终包后，原报障路径「排盘 → 毕法格局 → 展开」

### 16.2 两个根因

| # | 根因 | 说明 |

## 17. 工程链路加固：免费版同步的单一真源与打包门禁（2026-09-13，非用户可见）

### 17.1 起因（真机反馈修复期间暴露）

`APP/LiurenFocusDivinerFree` 是主版的**生成拷贝**，而「免费版 = 主版 + 差异规则」这个不变量
此前只在 **rawfile（数据侧）** 有硬断言，**源码侧一条都没有**。实际后果：主版改完
`components/PalaceCard.ets` 后直接编免费版，构建 **1.9 秒就 SUCCESSFUL** —— 编的其实是旧代码。

### 17.2 处置（原则：规则单一真源 / 判定只读 / 打包只消费判定）

| 件 | 改动 |
|:--|:--|
| `_tools/sync_free_edition.py` | 新增 `--check`：同一套差异规则**干跑到临时目录**，再与现存免费版逐文件比对（缺失/多余/内容不同），只报告不写盘；差异清单由规则自动得出，**无任何白名单**。仓库根改为 `__file__` 推导（`LIUREN_ROOT` 可覆盖）。 |
| `_tools/verify_free_edition.py` | 差异常量（`PAID_RAWFILE`）改为从 sync `import`，消掉重复那份；新增断言「**源码/配置树 = 主版 + 差异规则**」（判定复用 `sync.diff_against`）。 |
| `_tools/sign_release.py` | 工具链路径可被环境变量覆盖（`LIUREN_TOOLCHAIN`/`LIUREN_HVIGOR`/`LIUREN_JAVA`/`LIUREN_SIGN_TOOL`，缺失时给清晰提示）；**前置门禁**（free 目标跑 verify_free_edition，不过即中止、不构建、不出包）；**出包后校验**（verify_app_pkg）；**覆盖前自动归档上一刀**。打包脚本不实现任何同步逻辑。 |

### 17.3 为什么不「在打包脚本里同步」

sync 是「先清空再重建」：若打包顺带同步，则「真机装的树 / 出包的树」不再可追溯，失败会留半同步态，
更糟的是把「树没同步」这类问题**掩盖成一次成功出包**。打包脚本也不该承载「免费版怎么从主版推导」的
规则 —— 那是 sync 的知识。

### 17.4 验证（含变异测试）

- `--check` 与 `verify_free_edition` 在两种变异下**均变红**并报出确切文件与修法：
  ① 主版多一个文件（免费版缺）；② 主版文件改了未同步（内容不同）。还原后转绿，且**逐字节还原**。
- 打包前置门禁在同样变异下 **exit 1、未进入构建（无 `1. hvigor` 输出）、发布包逐字节未动** —— fail-fast 实证。
- 全链路一次实跑：前置门禁 PASS → assembleApp → 自动归档 → `verify-app success` → `verify_app_pkg` 16/16。
- **意外收获**：两次构建（同源码 + 同工具链）产物**逐字节相同** → release 出包具确定性，
  于是「包 ↔ 源码」可以直接比对（也解释了历史各刀字节差异都来自源码改动）。
