## 三、请重点看的四件事（体验维度，不是对错）

1. **情境立不立得住**：`brief` 是否让你一眼知道「何将何时、何日、谁问什么」。要素只取自该案 `input` 与 `original`（如 041 的「徐教授生年三十三」、042 的「何三公六十三岁」、045 的「吴公望问终身」、004 的「张九翁五十一岁」），没有编人物与结果。
2. **「取象链」是否说得通**：本批 4 案的原占都是**由四课与三传一步步推向古断**，例如
   平生案「初传申即日上神 → 申为日干之财而乘六合 → 中传亥乘贵人却落旬空（亥又是月将）→ 末传寅乘玄武而寅为丙火长生 → 日干丙火在卯月为休」；
   身位案「第四课上神子克丙火（鬼在四课）→ 干上神戌为丙火之墓又落旬空 → 中传巳与日干同气带生气 → 末传戌乘螣蛇而仍归日上 → 日干在未月为休」；
   张宅案「干上巳、支上亥两位皆为所生之地 → 初传巳即干上神乘勾陈带旬癸 → 中传寅即日支乘螣蛇带天马 → 末传亥乘太阴又来泄日干 → 日干庚金在戌月为休」。
   这条链有没有让你觉得「原来古断是这么来的」，还是太跳？
3. **线索是不是「引导」而非「告知」**：每条 `label` 是问句，`small` 写**能照着点的一处位置**（如「点三传『中传』的『乘将』行，再点下方事实栏的『旬空』，或点盘上中传之支所在格的『神煞』行」）——
   这是 §10 那条「锚点必须可点可达」的直接落地。请重点验证：**有没有哪一条你按 small 点不到**。
4. **长案有没有被「缩写」得失去味道**：本批四案原文 221–338 字，其中含大量**引擎不复算**的内容 ——
   042 的「带迷惑煞」「掘出十四穴」、041 的「曹姓人」「六曹」「绛帐」「黑煞为刑职」、045 的「十赴棘闱」「邓攸之哭」「觅一肖夫之妾以填补」、004 的「充役费用」「陈姓吏人」「亥数四、寅数七，乃十一年也」。
   我的处置是：**只取引擎能复算的那一段**（四课 / 三传 / 乘将 / 旬空 / 日干旺衰 / 神煞），原文的应期、数术、人物与应验一律不入支线，
   只在原占揭晓时由 App 揭 `original`（本批 4 案原占 `ending` 一律 `{type:"original", tip:"揭古断与应验"}`，不写 `ending.text` —— 这是第六批坑 1 定下的口径）。
   你觉得这样「瘦身」是否可惜？

**坑 2（工具链，工程性但很坑）：「4 个新键插在 `stories` 开头」的写法会让重复插入变得不可见**。
第一版生成器把新键插在 `"stories": {` 之后（为了保持既有行号不变）。第二次运行时，
`indexOf('"stories": {\n')` 仍命中同一处，于是**新块插在旧块前面**，文件里出现两套同名键（JSON 解析取后者）。
校验器读到的是旧文本，于是「明明改好了却还是 FAIL」。
- 修法：改用**纯 JSON 往返**（parse → 删同名键 → 末尾追加 → `stringify(indent 2)`），
  并在写盘后逐项复核「案数 / 4 案与草稿一致 / 既有案一字未变 / 无重复键 / 无孤立 LF」。
- 顺带记两条：① 随包 `case_story.json` 是 **CRLF**，用字符串切片插入时必须带 `\r\n`，否则文件混用换行；

**坑 3（口径复核）：`method` 锚点必须带 `ref`，且 `ref` 要等于复算课体名**。
本批四案复算课体分别为 **涉害（041）· 比用（042）· 比用（045）· 元首（004）**，四个锚点一律写 `{kind:"method", ref:"<复算值>"}`。
