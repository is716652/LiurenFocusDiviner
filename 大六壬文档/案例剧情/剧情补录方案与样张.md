**一句话思路**：剧情不是「写故事」，而是**把引擎对某一课已经算出的盘面事实，编排成一条可亲手取证的推演路径**；
断语不是「编」出来的，是从这些事实按古法通则推出来的——谁能复算，谁就是证据。

## 2. 作者契约（写一条支线必须满足的字段与硬校验）

### 2.1 结构（一条 story = 一案）

```
stories[<案例 id>] = { brief, note, asks[] }
```

- `brief`：情境（≥10 字）。**要素只能取自该案既有字段**（`input` 的月将/日干支/占时、`original` 的情境、`source`/`chapter` 的出处），**不得虚构**人物与结果。
- `note`：写「同一课可作多占（同课异占）」的说明（可沿用现有两案的写法）。

### 2.2 一条支线（ask）

| 字段 | 约束 |
|:--|:--|
| `id` | 非空且在同一案内唯一 |
| `role` | `original`（古籍原占）或 `derived`（同课异占） |
| `topic` | 必须在占类词表内（现 23 个：来意/疾病/官讼/行人/仕宦/生产/风水/应候/役事/终身/省试/会试/流年/前程/六甲/己身/复建/亡盗/远行/索债/赴任/复任/补官） |
| `title` / `intro` / `question` | 非空 |
| `badge` / `goodWords` | 呈现用（沿用现有两案风格即可） |
| `clues[]` | **非空**；每条 `{ id, label, small, anchors[], hint }` |
| `endings` | **必须恰好 4 档**（校验器硬判 `length === 4`） |
| `ending` | `{ type, text, note, tip? }`，且 **`ending.type` 必须等于 `role`** |

### 2.3 一条线索（clue）与锚点（anchor）

- `label`：**问句式引导**（如「先定课体：此课何名？」），不是结论句。
- `small`：点哪里取证（如「点『课名』」「点三传或盘上带马之宫」）。
- `anchors[]`：**至少 1 条**，形状以 `_tests/_test_case_story.js` 的 `switch(an.kind)` 为准（写错形状会被整批报错）：

  | kind | 形状 | 例 |
  |:--|:--|:--|
  | `method` | `{}` 或 `{ref:"<课体名>"}` | `"涉害"` / `"比用"` / `"伏吟"` / `"元首"` |
  | `chuan` | `{pos:"初传|中传|末传", ref:"<该位之支>"}` | `{pos:"初传", ref:"戌"}` |
  | `keg` | `{ref:"<干上神>/<日干>"}` | `"子/甲"` |
  | `jiang` | `{ref:"<支>/<将>"}` | `"戌/玄武"`（**不是** `zhi`+`ref` 两个字段） |
  | `gong` / `zhi` | `{ref:"<地支>"}` | `"申"` |
  | `xunkong` | `{ref:"<空亡之支>"}` | `"戌"` |
  | `dayWangShuai` | `{ref:"<本课日干旺衰值>"}` | `"死"`（**不是** `"甲/申"`） |
  | `shensha` | `{ref:"<支>/<神煞名>"}` | `"巳/驿马"` |
  | `hour` | `{ref:"<占时之支>"}` | `"申"` |
  | `shiGan` / `bianGan` | `{ref:"<中黄遁干>"}` | `"壬"` |

- `kind` 取值必须是这 12 种之一：
  `method`（课体）· `chuan`(+`pos` 初/中/末) · `keg`（四课）· `jiang`（支/将）· `hour` · `gong`（宫）·
  `zhi` · `xunkong`（旬空）· `dayWangShuai`（日干旺衰）· `shensha`（`ref` 形如 `巳/驿马`）· `shiGan` · `bianGan`。
  **每一个锚点都会被 `_test_case_story.js` 用引擎复算校验，落不到盘面即 FAIL。**
- `hint`：只说**盘面事实 + 古法/经文通则**；**不得抄录本案原文断语**（校验器用 **8 字窗口**在去标点后比对，命中即 FAIL）。

### 2.4 两类支线的口径差别（校验器硬判）

| | `original`（原占） | `derived`（同课异占） |
|:--|:--|:--|
| `hint` | 只给事实与通则，**留待呈上断语后再揭古断** | 同上 |
| `ending.text` | 揭**古断 + 应验**（引原文，标出处） | **只列「可参的取象清单」**，**不得含结论** |
| `ending.note` | 标原文出处 | **必写「非古籍原断」**并加现实免责 |
| 承诺式断语 | 古断可引（属原文） | **禁用**：校验器黑名单 `必得/必成/必死/必中/必至/必有/定主/确主/应验/必然/准有/发财/痊愈/无救/大凶/大吉/包好/一定` |
| 规则归属 | — | **必须出现**：`古法/经文/类象/原文/课经/常取/多主/宜/参看/取象` |

此外：全部文本**不得出现付费字样**（`付费/解锁/会员/VIP/价格/购买/订阅/充值`）。

## 3. 怎么补：一案六步（可复制）

```
① 复算      以该案 input 跑引擎，取「课体 / 四课 / 三传(支+遁干) / 三传乘将 / 旬空 / 日干旺衰 / 神煞(按支) / 助日」→ 这就是唯一可用的事实集
② 定 brief  用 input 的月将·日干支·占时 + original 的情境与出处，写成两三句，不加虚构
③ 定 asks   1 条 original + N 条 derived（占类取 §2.2 词表；derived 要**跨维度**，见 §5）
④ 写 clues  每条：问句 label → 点击位置 small → anchors（复算事实）→ hint（通则，不抄原文）
⑤ 写 ending original 设「呈上断语后揭古断+应验」；derived 列取象清单 + 「非古籍原断」+ 免责
⑥ 校验      node _tests/_test_case_story.js   然后   python _tools/export_case_story_web.py
```

**复算命令**（与校验器同一路径，保证锚点必然成立；**只读**，不写任何数据）：

```powershell
node _tools/case_story_facts.js <案例 id>    # 打印该案 input/original + 引擎复算事实（课体/三传/乘将/旬空/旺衰/神煞/助日）
```

> 现有：`_tools/case_story_facts.js`（本轮扶正，只读）。
> 下一步建议把它扩成 `_tools/case_story_scaffold.js`：直接输出**可填的 story 骨架 + 事实清单**（见 §7）。

## 4. 断语为什么能保证正确（四层）

1. **锚点即证据（机器判）**：每条 clue 的每个 anchor 都要在**引擎复算**的盘面上命中——课体名、四课、三传及其位置、乘将、旬空、宫、支、日干旺衰、神煞、遁干。
   锚点是「这句话的盘面依据」，落不到即校验 FAIL。
2. **防剧透（机器判）**：hint 与本案 `original` 做 **8 字窗口**比对，抄了原文断语即 FAIL —— 逼作者只给事实与通则，把「断」留给用户在 ending 里对。
3. **口径分层（机器判 + 人写）**：`original` 才可引古断与应验；`derived` 只能列取象清单、禁承诺式断语、必标「非古籍原断」与现实免责。
   这与 App 内「原文 ·」分层显示一致。
4. **出处可查（人判，纪律）**：引经据典必须能在仓库内找到出处（类象库/经文/《中黄五变经》等）；不确定处标「（原阙）」，不补脑。

**建议审核通过后补的三条断言**（都是结构判据、不碰定法）：

| 新断言 | 判据 | 防的是什么 |
|:--|:--|:--|
| D1 `derived` 的 `ending.text` 不得含结论 | 复用现有 `VERDICT` 黑名单扫 `ending.text` | 现在只扫了部分文本，收尾句可能漏网 |
| D2 锚点覆盖面 | 每案 anchors 至少覆盖 `method/chuan/jiang/gong` 四类中的 3 类 | 防止「只在课名上挂锚点」的空壳剧情 |
| D3 支线配比 | 每案 ≥1 `original` + ≥1 `derived` | 保证「同课异占」的产品卖点每案都在 |

## 5. 怎么让情节更好看（七法，均以现有两案为范式）

1. **三幕结构**：情境（brief）→ 取证（逐条 clue，用户亲手点盘）→ 呈上断语与揭古断（ending）。取证段是教学，揭断段是钩子。
2. **线索写成问句**：「先定课体：此课何名？」「占行人先看动象：马在何处？」——让用户先想，再给通则提示。
3. **derived 支线跨维度**：不要三条支线都问「吉凶」。按取象维度分工，例如
   **动象**（驿马/天马/初传）· **音信**（朱雀/皇书/生气）· **阻隔**（玄武=水隔、白虎=病隔）· **终局**（末传+所乘将）· **己身**（日干旺衰）· **天时**（月令/寒暖）。
4. **原占必揭古断与应验**：古籍案例多有明确应验（本案「七日而殒」），这是最强的钩子，也让用户看到「盘面 → 断语」的落差。
5. **事实与推演要能分开看**：hint 只给事实（机器保证不含原文断语），ending 才给判断——用户能清楚区分「软件陈述」与「古人原断」。
6. **史实不虚构**：人物、时间、地点、结果一律取自案例既有字段；缺的就留白或标「（原阙）」。**不编应验**。
7. **一案一主题**：每案给一个「看点」标签（现有 `badge` 字段），让人一眼知道这条支线教什么（如「课体入门」「动象」「阻隔」）。

## 7. 43 案排期与排序建议

- **批次**：建议按 `chapter`/出处分批，每批 6–8 案（一批一提交，便于校验与回滚）。
