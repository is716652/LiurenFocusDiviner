# 素材地基：古籍语料普查与入库管线（提案）

> **为什么有这份文档**：收费块的定位已从「45 条案例陈列」转向**「一局一剧情」**（见
> 《古籍案例鉴赏-设计与进度》开头定位段）。案例不删 —— 它们是**素材地基**，剧情从地基里长出来。
> 用户会继续以 md 形式投喂新古籍案例，选题范围随之扩大。
>
> 那么第一件必须回答的事是：**手里这批原始语料到底还能撑起多少剧情，哪一本最值得先做？**
> 本文就是这次普查的结果，外加一条入库管线的提案，供决策。
>
> 性质：**盘点 + 提案**，不含任何代码改动。数字为 2026-09-22 实测快照；
> 普查脚本为一次性工具，已删（方法见 §2，可原样重写）。
> 最后核对：2026-09-22。

## 1. 结论先行

1. **手里有一处被完全忽略的大矿**：《六壬直指御定》不是案例书，而是 **720 局（60 日干支 × 12 局）的完整断语库**，
   实测 **717 条**，每条自带课体、课义、解曰、断曰、以及**按占类分列**的断语（天时/家宅/婚姻/疾病/求财/遗失/行人/出行…每局 6–12 类）。
   它此前被当成"乱码文件"跳过 —— 实际是 **UTF-16** 编码，内容完好。
2. **量级对比**：现入库 45 案；《六壬断案》211 课式只用了 8；《六壬直指御定》717 局**一局未用**。
3. **它比案例更适合「剧情化」**：每局标注「干上神」，**课体可由引擎复算对账**（引擎已输出 `sanchuan.keti`），
   等于 717 条自带验收标准；且**同一天干 12 局天然成序列** —— 正是"一个一个做成不同剧情演进"的结构。
4. **编码是入库第一道坎，且不能假定 GBK**：28 个 txt 里 20 个 GBK、6 个 UTF-8、**2 个 UTF-16**。
5. **入库管线建议**：编码探测 → 切条 → 抽字段 → **引擎复算对账** → 落库为**素材**（不带剧情、不带合规套话）
   → 剧情层另写。素材与剧情分离，才能让"继续投喂 md"不打断剧情生产。

## 2. 普查范围与方法

| 项 | 内容 |
|:--|:--|
| 目录 | `大六壬文档/壬占汇选/`、`大六壬文档/古籍原文-易藏-术数/` |
| 文件 | **42 个** = 28 txt + 5 docx + 9 md |
| 编码探测 | 依次试 `utf-8-sig` → `gb18030` → `utf-16`，取**汉字字符最多**的解码 |
| 课式行判定 | 同一行**同时**出现 60 甲子中的「X日」与「X将X时」 |
| 局条目判定 | `X日第N局 干上Y`（N 含十一、十二） |

**两条普查纪律**（都是这次踩出来的）：

- **必须去重**：同一本书常有 `.txt`（GBK）与 `.utf8.txt`（UTF-8）两份，
  实测《六壬断案》两份**内容完全相同**（`sha1 d4fe776f071bbef6`），
  分别计数会把课式数**凭空翻倍**（211 → 422）。
- **不能假定 GBK**：按 UTF-8 打开 UTF-16 文件不会报错，只会显示成"乱码"，
  于是文件被误判为损坏而跳过 —— 《六壬直指御定》就是这样被漏掉的。

## 5. 重点发现：《六壬直指御定》= 720 局断语库

### 5.1 它长什么样（原文实拍：甲子日第一局）

```
甲子日第一局 干上寅
  课体：伏吟，元胎。
  课义：两贵差跌，六虎陈列，病讼皆畏，仕宦怡悦。
  解曰：昼贵临于夜地，夜贵临于昼地，谓之贵人差跌。干贵者，事多参差，不能归一。……
  断曰：此自任之卦，又曰元胎，利静不利动，利上不利下，利君子不利小人。……
  天时：水火伏匿，龙神入庙，无雨有风。谋望：先难后易。家宅：恐有动迁，夜占防孝服。
  婚姻：不利，昼占女子美好；夜占女子丑恶。疾病：主失音，肝家受病，肾水枯竭，宜清金滋水。
  胎孕：聋哑。求财：不甚得意，防人暗害。捕获：女人在西北，男人在正南，俱不出境。
  遗失：在家中。行人：远者回转，近者将至。出行：宜从旱路。征伐：玉帐经云……
  毕法云：虎临干鬼凶速速，日乘旺禄休狂妄，虎乘遁鬼殃非浅，宾主不投刑在上。
  吴越春秋，三月酉时范蠡占吴王病，三传寅巳申，德禄在寅，病在巳，绝在申，春木旺金囚，无伤也。……
```

（`甲子日第十二局 干上卯 → 课体：重审，进茹`，体例一致。）

### 5.2 为什么它是**最合用的素材源**

| 优势 | 说明 |
|:--|:--|
| **自带验收标准** | 每条首列「课体」，而引擎已输出 `sanchuan.keti`（伏吟/元胎/重审/进茹/斩关…）→ **717 条全部可自动对账**，不用人工判对错 |
| **按占类分列** | 天时/谋望/家宅/婚姻/疾病/胎孕/求财/捕获/遗失/行人/出行/征伐…直接对齐 App 的占类体系，**不需人工归类** |
| **天生成序列** | 同一天干 12 局 = 12 个盘面 → 天然是"一天干一条剧情线"，正好接住"一个一个做成不同的剧情演进" |
| **附毕法条文** | 「毕法云」段落与 App 的 `bifa`（毕法赋）功能**同源**，可交叉引用 |
| **偶附史例** | 如甲子日第一局引《吴越春秋》范蠡占吴王病，可作剧情锚点 |
| **出处最硬** | 清代**御定**、书名明确 → 合规口径（C3 出处纪律）最好写 |
| **规模** | 717 局 × 6–12 类 ≈ **5000–8000 条断语**，远超 45 案的承载量 |

### 5.3 完整性核查（717 / 720）

| 缺口 | 实测 |
|:--|:--|
| **戊辰日 12 局全缺** | 全文连「戊辰日」三字都 **0 次**（确证缺页/原缺，非正则问题） |
| 丙戌 / 乙巳 / 壬戌 各缺 1 局 | 3 局（也可能是排印格式异常导致漏匹配，**待人工复核**） |
| 戊寅日 多 12 条 | 实测 24 条（该日疑被排印两遍），**入库时需去重** |

> 注意：**戊辰日** 正好是 `大六壬文档/壬占汇选/` 里已有 5 案入库的那一天干；
> 直指御定缺戊辰，壬占汇选有戊辰 —— 两个来源可以互补，但不要指望在直指御定里找戊辰日。

## 7. 入库管线提案（待批）

```
原始文件（GBK / UTF-8 / UTF-16 混杂）
  ↓ ① 编码探测 → 统一转 UTF-8，输出到 _build/（原文目录一字不动）
  ↓ ② 切条：直指御定按「X日第N局 干上Y」，案例书按「X日 … X将X时」
  ↓ ③ 抽字段：干上神 / 课体 / 课义 / 解曰 / 断曰 / 分占类 / 毕法云 / 附例
  ↓ ④ 引擎复算对账：课体必须与 sanchuan.keti 一致
  ↓    不一致 → 进人工复核队列（**绝不静默丢弃**）
  ↓ ⑤ 落库为素材：material_*.json（只存盘面事实 + 原文，**无剧情、无合规套话**）
  ↓ ⑥ 剧情层另写：从素材里挑局，套《剧情补录方案与样张》的写案契约
```

设计要点：

- **素材与剧情分离**：用户继续投喂 md 时，只跑 ①②③④⑤，**不打断**剧情生产；剧情按选题从素材里挑。
- **对账优先于入库**：引擎算不出来的（课体不符、月将不明、日期不全）一律进复核队列，宁可少收不可错收。
- **不写断语套话**：素材层只保留原文与盘面事实 —— 断语的措辞与合规口径由剧情层按
  《断语措辞与合规口径-分级与改写清单》统一处理，避免两处各写一套。
- **素材是否入 git**：原文总量在百万汉字级，建议**只入提取后的 JSON**（原文留在 `大六壬文档/`），
  避免仓库膨胀。

## 9. 本次普查的副产品：两条踩坑记录

1. **不要假定 GBK，也不要假定"乱码 = 坏文件"** —— 先试 `utf-8-sig`/`gb18030`/`utf-16` 三种取汉字最多者。
2. **同名双文件要按内容 sha1 去重** —— `.txt` 与 `.utf8.txt` 常常同内容，分别计数会翻倍。

（这两条已并入 `Agent.md` §9 的踩坑清单。）
